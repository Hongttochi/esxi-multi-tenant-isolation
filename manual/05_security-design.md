# 05. 보안 설계

## 5.1 기본 원칙

본 시스템은 보안 중심 설계를 기반으로 하며, 다음 원칙을 기반으로 운영된다.

- Default Deny 정책 적용
- 최소 권한 원칙 (Principle of Least Privilege)
- 관리 네트워크 완전 분리 및 보호

---

## 5.3 vCenter 계정 및 권한 분리 (RBAC)

각 팀은 vCenter 내에서 독립적인 계정을 할당받으며, Role-Based Access Control(RBAC)을 기반으로 권한이 제한된다.

### 권한 범위

- 할당된 Resource Pool 내에서만 VM 생성 가능
- VM 삭제 권한 허용
- 타 팀 VM 접근 금지
- 클러스터 설정 변경 불가
- 네트워크 설정 변경 권한 없음

---

### 적용 방식

- Resource Pool 기반 자원 분리
- Folder 기반 객체 격리
- Custom Role 기반 권한 설정

---

### 보안 효과

- 관리 권한 오남용 방지
- 인프라 설정 보호
- 팀 단위 책임 운영 구조 확보

---

## 5.4 내부 보안 정책

- 팀 간 네트워크 통신 차단
- 관리 인터페이스 외부 접근 차단
- ESXi 직접 외부 노출 금지
- 모든 관리 트래픽은 내부 관리망에서만 허용

---

## 5.5 보안 목표

본 시스템의 보안 목표는 다음과 같다.

- 무단 접근 방지
- 내부 네트워크 확산 방지
- 네트워크 경계의 명확한 분리
- 중앙 통제 기반 보안 정책 유지
