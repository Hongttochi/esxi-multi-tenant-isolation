# 04. 네트워크 세그멘테이션

## 4.1 주소 체계

전체 네트워크는 `172.16.0.0/16` 대역을 기반으로 구성되며, 각 팀은 독립적인 `/24` 서브넷을 할당받는다.

- **Team A**: 172.16.1.0/24  
- **Team B**: 172.16.2.0/24  
- **Team C**: 172.16.4.0/24  
- **Team D**: 172.16.3.0/24  
- **Team E**: 172.16.5.0/24  

각 팀은 독립적인 브로드캐스트 도메인을 가지며, IP 충돌 및 간섭을 원천적으로 차단한다.

---

## 4.2 설계 목적

본 네트워크 세그멘테이션의 주요 목적은 다음과 같다.

- Broadcast Domain 분리
- 팀 간 Layer 3 통신 차단
- pfSense 기반 중앙 통제 구조 구성
- 보안 경계 명확화 및 공격 표면 최소화

---

## 4.3 VLAN 전략

각 ESXi 호스트 내부의 vSwitch는 물리 스위치와 연계되어 있으며, VLAN 기반으로 논리적 네트워크 분리를 수행한다.

외부 노출 포트가 다수 존재하는 환경 특성상, 물리적 분리만으로는 한계가 있어 VLAN 기반 논리 격리를 추가로 적용하였다.

이를 통해 동일 인프라 내에서도 팀별 네트워크를 독립적으로 운영할 수 있도록 구성하였다.

---

## 4.4 관리 네트워크

관리 네트워크는 ESXi 및 vCenter 관리를 위한 전용 네트워크로 분리되어 있다.

- vCenter Management
- ESXi Host Management

해당 네트워크는 외부에서 직접 접근이 불가능하며, 내부 관리 목적에 한정된다.

## 4.6 팀 간 격리 방식

팀 간 네트워크 격리는 pfSense 기반 정책으로 강제된다.

- 방화벽에서 팀 간 라우팅 차단
- 각 팀은 독립 VLAN 및 서브넷 사용
- 직접 WAN 접근 금지
- 모든 외부 트래픽은 pfSense를 통해서만 처리

이 구조를 통해 팀 간 네트워크 간섭을 원천적으로 차단하고, 중앙 집중형 보안 정책을 유지한다.
