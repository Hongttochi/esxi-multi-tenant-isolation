## 03. 자원 할당 전략

### 3.1 기본 원칙

본 시스템의 자원 할당은 다수 팀이 동일한 조건에서 독립적으로 서비스를 운영할 수 있도록 설계되었다.  
이를 위해 다음과 같은 원칙을 기반으로 자원을 구성하였다.

- 팀별 독립 VM 구성
- 팀 간 리소스 균등 분배
- 자원 경합 최소화
- 예측 가능한 성능 보장

---

### 3.2 팀별 자원 할당 기준

제한된 물리 자원 환경에서 5개 팀이 동일한 조건으로 서비스를 운영할 수 있도록 **팀 단위 균등 분배(공평 분배)** 전략을 적용하였다.

- **Memory**: 팀당 40 ~ 50GB
- **CPU**: 각 ESXi 호스트 기준 팀별 vCPU 할당 (서비스 요구사항에 따라 상한 설정)
- **SSD**: 총 340GB 범위 내 팀별 스토리지 분리
- **HDD**: 총 1.8TB 범위 내 팀별 스토리지 분리

본 구조의 목표는 특정 팀이 자원을 선점하는 방식이 아니라, 모든 팀에게 **최소 보장 자원(Minimum Guaranteed Resources)**을 동일하게 제공하는 것이다.

---

### 3.3 스토리지 운영 전략: 로컬 디스크 기반 분리 (A안)

본 환경은 물리 ESXi 호스트가 분리된 구조이며, vSAN과 같은 공유 스토리지를 사용하지 않고 각 호스트의 로컬 디스크를 기반으로 팀별 스토리지를 분리하여 운영하였다.

#### A안 vs B안 비교

| A안: 로컬 디스크 기반 분리 (채택) | B안: vSAN 기반 통합 |
|----------------------------------|----------------------|
| <img width="100%" src="https://github.com/user-attachments/assets/f8df2267-2043-4d3c-b06e-b1c112608d5f" /> | <img width="100%" src="https://github.com/user-attachments/assets/013aacf2-ea5d-4999-97db-90aeb691dd6d" /> |
| - 물리 디스크 기반 분리 | - 공유 스토리지 기반 |
| - 팀 간 I/O 완전 분리 | - 통합 스토리지 풀 |
| - 오버헤드 낮음 | - 확장성 높음 |

---

#### 선택 이유

- **격리 강화**
  - 스토리지를 물리적으로 분리하여 특정 팀의 I/O 부하가 다른 팀으로 확산되는 것을 방지
- **독립성 우선**
  - 고가용성(HA) 일부를 포기하는 대신 팀별 실사용 자원 확보를 우선
- **오버헤드 최소화**
  - vSAN 사용 시 발생하는 CPU / 네트워크 / 스토리지 오버헤드 제거
- **운영 단순화**
  - 교육 및 프로젝트 목적에 맞게 구조를 단순화하고 설계 의도를 명확히 유지

---

### 3.4 트레이드오프 (의도된 설계 선택)

| 항목 | 로컬 디스크 분리 (A안) | vSAN 통합 (B안) |
|------|------------------------|------------------|
| 가용성 (HA) | 낮음 | 높음 |
| 자원 오버헤드 | 낮음 | 상대적으로 높음 |
| 팀 간 I/O 간섭 | 낮음 (강한 격리) | 상대적으로 높음 |
| 확장성 / 유연성 | 낮음 | 높음 |
| 운영 난이도 | 낮음 | 높음 |

본 프로젝트는 고가용성보다 **격리성과 실사용 자원 확보**를 핵심 목표로 설정하였기 때문에 A안을 최종 채택하였다.

---

### 3.5 고려 사항

- CPU Overcommit 최소화
- Memory Reservation 적용 검토
- 스토리지 공유 의존성 제거

---

### 3.6 개선 가능성

향후 확장 및 고도화를 고려하여 다음과 같은 개선이 가능하다.

- Resource Pool 기반 QoS 정책 적용
- DRS 기반 자동 자원 분산 구조 도입
- 팀별 리소스 사용량 모니터링 및 자동 제한 정책 구축
